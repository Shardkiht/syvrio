# 记忆检索与联网搜索评测

[2026-11-22 合成库实测报告](reports/2026-11-22-recall.md)记录了默认返回 7 条和 10 条的逐题配对结果、漏掉的证据和上下文开销。

## 如何判断检索是否准确

主基准 [recall_gold.json](data/recall_gold.json) 给每个问题预先标出回答所需的事实，每个事实包含对象、时期、字段和具体值。记忆正文单独写入合成 Vault。题目、答案表和干扰项标注仅供评分器使用。例如询问两门课各自的地点，两份材料都写到同一门课只能覆盖其中一个地点。询问旧地点时，新地点属于已标注的干扰项。

两次运行分别把临时默认返回数设为 7 和 10，按相同问题调用产品的 `recall` 工具，调用参数都省略 `limit`。评分器解析最终送给模型的工具消息，核对 ID 和正文，再按以下口径逐题计分。

| 指标 | 含义 |
| --- | --- |
| 证据齐全题数 | 一题所需的每个独立事实都至少有一条材料支持。另列各题平均事实覆盖比例。 |
| 文档 Recall@K | 返回的相关记忆条数占题库中全部相关记忆条数的比例。同一事实的独立佐证可以各计一条。 |
| Precision@K / 实返精度 | 前者除以 K，后者除以实际返回条数。相关条目很少时，增大 K 本身就会摊低前者。 |
| nDCG@K | 按返回位置给相关条目折算分数，排在前面的权重更高。 |
| 干扰与缺证 | 对有答案题统计已标注的干扰项抢在首条正确证据之前的次数。对库中无答案题单列返回候选和命中已标注干扰项的次数。 |

先按题算各比例，再在有答案题上取平均，每题权重相同。无答案题单列。另列需要 1 个、2–7 个、超过 7 个事实的题数，便于看出返回条数的容量限制。工具正文的平均 token 数包括所有题。生成回答是否正确需要单独测量。

## 运行与复核

```bash
uv sync --extra local-embed
uv run python -m evals.recall_gold_eval --json /tmp/syvrio-gold-hybrid.json
uv run python -m evals.recall_gold_eval --keyword --json /tmp/syvrio-gold-keyword.json
uv run python -m evals.conversation_recall_eval --method hybrid --details
uv run python -m evals.conversation_recall_eval --method keyword --details
uv run python -m evals.retrieval_eval --json /tmp/syvrio-frozen.json
uv run python -m evals.retrieval_eval --keyword --failures
uv run python -m evals.short_facts_eval --details
uv run python -m evals.field_lookup_eval
uv run python -m evals.memory_eval
```

首次跑混合检索需能取得本地嵌入模型。模型已缓存时可设 `HF_HUB_OFFLINE=1` 离线复跑。关键词入口无需嵌入模型。各基准使用临时 Vault、配置和 Runtime。向量降级会使该轮测评失败。金标 JSON 报告包含数据哈希、每题的预期值、实际排名和可核对的记忆原文。

| 入口 | 覆盖范围 |
| --- | --- |
| [金标检索](recall_gold_eval.py) | 61 条记忆、52 个独立事实、30 题。包含新旧值、近似名称、自然口语、多事实和无答案题。 |
| [会话自动召回](conversation_recall_eval.py) | 12 个合成会话。通过实际 Agent 入口测是否触发、自动注入的证据，再用冻结的独立查询对照显式工具；使用无密钥时的查询改写回退路径和记录输入的替身模型。 |
| [历史冻结题库](retrieval_eval.py) | 1,000 条记忆、50 题。分别测底层 BM25、向量、混合检索和实际工具。旧题以任一预标 ID 命中计 Hit@K，保留作版本对照。原始生成器仅供人工更新冻结题库，其运行需要单独的模型调用。 |
| [短字段](short_facts_eval.py)与[字段重叠](field_lookup_eval.py) | 在大量干扰记录中查姓名、设备等短值和相近标签。短字段的 9 个有明确答案的问法单独计分，“我是谁”作为观察项。 |
| [解析与裁决](memory_eval.py) | 固定合成抽取结果，核对候选入库、重复、冲突、低置信与敏感内容、时间、地点、情绪以及历史状态检索。 |

## 联网搜索聚合评测

[web_search_eval.py](web_search_eval.py) 使用固定候选和人工相关性标注，在不联网的情况下复现路由、URL 去重、provider 顺序、回退和数量停止。人工标注只用于离线测量最终返回的相关性，不参与生产路由，也不会触发自定义评分或重排。可运行：

```sh
uv run python -m evals.web_search_eval
uv run python -m evals.web_search_eval --compare evals/web_search_baseline.json
```

基线 JSON 保存当时的离线结果，不代表当前线上供应商质量。分析结果变化时，固定候选比较适配器原始顺序、跨 provider 交错和最终输出，再用相同请求预算核对去重后补足与停止位置，避免把上游漏查和回退不足混在一起。确定性契约由 `tests/infra/search/test_search_aggregation.py` 的 fake provider 回归覆盖；真实供应商可用性单独做低频冒烟，标明空结果、超时和限流。

### 聊天工具按默认条数调用

对每道题调用聊天使用的 `recall` 工具，省略 `limit`，核对返回给模型的目标 ID 和正文。11 月 21 日另在同一工作区对每道题显式传 `limit=7`，与新默认的 10 条配对复测。三轮结果如下。

| 被测版本 | 默认最多返回 | 目标出现在返回结果中的题数 | 命中率 |
|---|---:|---:|---:|
| 重构前 | 8 条 | 49/50 | 98% |
| 重构后，11 月 20 日 | 7 条 | 48/50 | 96% |
| 调整默认值后，11 月 21 日 | 10 条 | 49/50 | 98% |

新默认值下 50 次工具调用均成功，各题的前 7 个结果 ID 及顺序与显式传 7 时一致。按前 1、3、5、7、8、9、10 条截取，分别命中 **40、45、48、48、49、49、49 题**。同一批查询里，按项目的 `estimate_tokens` 估算，单次工具返回文本平均从 **488.7 tokens** 增至 **703.3 tokens**（约 +44%）。此处只统计工具返回文本。

|---|---|
| 我叫什么名字来着？ | 第 4 条 |

## 2026-11-10 历史结果（LLM 生成冻结数据）

控制变量：两分支运行同一份 `evals/retrieval_eval.py`，读取同一份冻结的 `evals/data/*.json`（1000 条语料 / 50 题，含主题复述、口语改写、字段查询、数字干扰、低词面重叠）；解释器 CPython 3.12.14，本地 `BAAI/bge-small-zh-v1.5`，top-k=10。被测代码 main `703e969`（0.3.4）与当时的 evolution 工作区（未记录固定提交，因此结果不能作为当前 HEAD 的验收）。

语料特征（生成语料自身，冻结可复现）：1000 条，长度中位 47、P90 66，汉字占比 0.596，含冒号 46.2%，含“的”62.7%，中英混排 98.1%；生成时已过滤邮箱/URL/手机号/身份证号/车牌等个人信息模式。

main（`703e969`）：

| 检索 | Recall@3 | Recall@5 | MRR@10 |

| keyword | 84% | 84% | 0.820 |

结论：keyword 两分支逐项相同；vector 召回相同、MRR@10 高 0.010；evolution 的 hybrid 仅 Recall@3 +2pp（88%→90%）、MRR@10 +0.005。逐题看只多救回 1 题（Roland FP 90X 键盘：查询含 ASCII 型号词，字面闸保留精确命中），其余 hybrid 失败题的目标不在 keyword/vector 任一候选池内，融合无法补回。50 题中 1 题即 2pp，单分类仅 2–7 题时 1 题可达 14–50pp，因此分支差异在表面上很小。未发现指标回退。

字段查询已并入 50 题（identity 分类 71%/86%/86%）：含标签词的“邮箱前缀/偏好语言/常住城市/血型”三路都过；“我今年多大”因不含“年龄”而 keyword 失败；“我叫什么名字”被“昵称”条目干扰，三路都失败。数字干扰与低词面重叠题多数通过，失败集中在语义相近条目的排序。

## 历史（2026-10-30，旧题集）

范围：main 与 evolution，同一解释器与本地 `BAAI/bge-small-zh-v1.5` 模型；456 条合成记忆 / 27 个固定用例。旧脚本按可接受子串判命中，指标为 Hit@K（当时称 Recall@K），不能与当前按目标 ID 判分的结果直接比较。两分支指标相同。

| 检索 | Hit@3 | Hit@5 | Hit@10 | MRR@10 |
|---|---:|---:|---:|---:|
| keyword | 74.1% | 74.1% | 74.1% | 0.722 |
| vector | 92.6% | 92.6% | 96.3% | 0.913 |
| hybrid | 92.6% | 92.6% | 96.3% | 0.913 |

结论：未发现基础检索命中率回退；混合检索在合成改写题上有效。旧题集与当前 1000 条冻结语料、50 题的题集不同，数字不可直比。


## 历史结果（2026-10-25，BAAI/bge-small-zh-v1.5 本地推理）

| 检索方式 | Recall@3 | Recall@5 | MRR@10 |
| --- | --- | --- | --- |
| keyword | 67% | 67% | 0.667 |
| vector | 89% | 89% | 0.815 |
| hybrid | **89%** | **89%** | 0.815 |

分类 Recall@3：hybrid 在原词 / 身份上与向量单路持平且由两路融合保障；数字类从 50% 升到 75%（hybrid 增加 keyword 命中的字面覆盖闸：查询的 CJK bigram 在命中条目覆盖率 < 0.3 视为虚匹配，不参与 RRF——此前干扰项的 BM25 高名次会把向量路的正确结果挤下去）。跨语言 50% 是 bge-small-zh 的模型局限，agent 查询改写已要求非中文问题补充中文说法，根治需换 multilingual embedding 模型。

## 旧题集观察（不代表当前分组指标）

- 身份类超短条目（如"姓名：X"）受小节前缀稀释和同义词（姓名↔名字）影响，三路 Recall@3 均低。
- 数字类小样本（4 例）下 hybrid 会被共享前缀的同小节条目挤占。
