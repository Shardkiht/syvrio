# Syvrio 产品路线图

- 文档状态：现行规划
- 更新日期：2026-11-15
- 规划方式：Now / Next / Later + 持续工程
- 产品边界与验收原则见 [PRD.md](PRD.md)

本路线图安排方向、依赖和晋级条件，不虚构固定发布日期。具体 issue、提交和发布状态以 GitHub、CI 与实际验收报告为准。

## 1. 当前基线

Foundation 已具备个人记忆、Markdown Vault V2、UTC 时间规范、TUI/Web/CLI/MCP、模型设置、搜索抓取、迁移和构建能力，并已进行全量测试、合成迁移演练、真实 Spark 主流程与断线验收。

当前定位是**正式版候选**，不是已经替换 main 的既成事实。自动模型候补已按产品决策从 Foundation 移除；模型失败直接反馈，用户手动切换模型。

Evo 继续承载时间演化、推断审查、画像和 Dreaming 等高级记忆能力。共享基础设施应减少分叉，Foundation 的记忆行为不随 Evo 自动变化。

## 2. 优先级原则

按以下顺序安排，而不是按“功能看起来是否先进”排序：

1. **数据与隐私**：防丢失、防错写、可恢复、凭据和推理隔离。
2. **正常使用回归**：会话、断线、停止、Undo、滚动、模型切换和迁移。
3. **发布可信度**：真实终端、CI、构建、分发和文档一致。
4. **合并成本**：Web、TUI、模型、搜索、构建等共享组件对齐。
5. **记忆能力演进**：先在 Evo 证明质量和可控性，再决定是否进入 Foundation。

## 3. Now — Foundation 正式版收尾

### N-01 修复 Web 流式自动跟随

- 处理 `MessageList` 程序 smooth scroll 的中间事件被误判为用户滚动的问题。
- 明确“用户主动阅读历史”与“程序自动滚动”的状态边界。
- 增加真实流式结构回归测试，并在真实浏览器验证长回复、工具事件、切换会话和回到底部。

**完成标准**：无用户输入时持续跟随；用户主动上滑后暂停；接近底部或明确回到底部后恢复；历史与生成状态不受影响。

### N-02 完成手机与真实浏览器生命周期验收

- 覆盖生成中返回首页、切后台、锁屏、关闭页面、重新进入、显式停止和多标签。
- 区分浏览器断线、页面隐藏、网络中断、进程退出和用户取消，不把所有情况都显示成“已停止”。
- 验证完成后回复只保存一次，重连能读取，interrupted 标记仅用于真实取消或中断。

**完成标准**：目标浏览器与手机 WebView 的可复现用例全部有结果；未覆盖平台明确记录，不用 jsdom 代替实机结论。

### N-03 完成提交审查与 CI 验收

- 将当前大规模未提交工作树按逻辑边界审查，确认未跟踪模块、测试、脚本和 Web 源码全部纳入预期范围。
- 检查自动模型候补移除、P3 文档修复和新增产品文档后的最终差异。
- 在 Debian 13 上通过 GitHub Actions 的 Python、前端和打包检查。
- 保留构建包、测试报告和迁移报告，不把临时探针或个人 Vault 纳入提交。

**完成标准**：暂存与未跟踪清单明确，CI 通过，工作树可复现，审查没有未处置的 P0/P1 或发布阻塞 P2。

### N-04 受控替换稳定主线并准备发布

- 只有在 N-01 至 N-03 完成后，才评估 Foundation 替换 main。
- 发布前重新确认版本号、更新器识别规则、迁移顺序、回滚路径和分发包内容。
- main 替换、提交、推送、GitHub Release 和 PyPI 发布分别获得项目所有者授权，不自动串联执行。

**完成标准**：稳定主线和发布包指向同一已验收提交；旧版本与旧 Vault 有明确恢复路径。

### N-05 建立现行文档入口

- 以 `docs/PRD.md`、`docs/ROADMAP.md`、`docs/architecture.md` 为方向与技术总览。
- README 保留用户向摘要并链接现行文档，避免继续堆叠实施日志。
- 在现行文档中维护最新约定，早期方案和审查查阅 Git 历史。

**完成标准**：新开发者能从文档索引区分产品决策、当前架构、未来计划和历史记录。

## 4. Next — 共享基础设施收敛与兼容性补验

### X-01 搜索与抓取实现对齐

- 对 Foundation 与 Evo 的 Search/Fetch 契约、router、provider adapters、缓存、用量和质量门控做逐文件差异审查。
- 优先合并通用错误修复和资源管理，不强行改变 Foundation 的记忆检索行为。
- 保持搜索引擎/provider 回退；不得与已移除的模型候补混淆。

**完成标准**：共享搜索组件差异有明确理由，通用缺陷修复可双向移植，现有搜索质量和工具协议测试通过。

### X-02 模型与供应商兼容矩阵

- 在受控次数和合成提示词下补验主要供应商的流式、非流式、工具调用、取消、超时和错误格式。
- 覆盖代理、SSL、私有 CA 和外部共享 client 的所有权边界。
- 保持 Foundation 手动模型切换，不恢复 `fallbacks`。

**完成标准**：每个供应商分别标记 mock 通过、真实通过或未验证；失败直接呈现且资源正确释放。

### X-03 Web/TUI 通用交互双向修复

- 将纯 UI、滚动、队列、取消、设置和生命周期缺陷区分为共享缺陷或分支专属行为。
- 共享修复尽量使用相同实现与测试，避免同一问题在两个分支分别演化。
- Evo 专属 dream/profile/inference review 不进入 Foundation 命令目录或直接调用路径。

**完成标准**：同源组件可较干净合并，分支差异主要集中在明确的产品能力与记忆行为。

### X-04 构建与依赖持续验收

- 保持锁文件、Ruff、前端 TypeScript/Vitest、生产 Web 构建和 wheel/sdist 检查一致。
- 在干净环境验证 CLI 与 Web 静态资源，持续执行污染扫描。
- 可选依赖保持可选，缺失时跳过或降级的原因清晰可见。

**完成标准**：同一提交可重复构建，安装产物不包含本地配置、用户数据、探针或构建缓存。

### X-05 远程访问边界评估

- 当前 Web 无登录认证，默认仅 loopback。
- 在增加任何远程访问承诺之前，先明确认证、Host/Origin、TLS、反代和日志保留责任。
- 不把自托管诊断日志的设计确认扩展成“可直接暴露公网”。

**完成标准**：要么继续明确只支持受信环境，要么形成独立安全设计与验收，不做模糊承诺。

## 5. Later — Evo 高级记忆演进

以下能力不是 Foundation 当前正式版的缺失项。先在 Evo 形成可量化的质量收益、用户控制和迁移方案，再决定是否晋级。

### L-01 记忆上下文：时间、地点、情绪

对应既有方向 Issue #10。

- 补原始时间锚点、相对时间解析和可审查的情绪推断。
- 区分事实发生时间、记录时间和有效日期，保持日期精度。
- 评估这些字段对召回的真实增益，避免为了结构化而结构化。

### L-02 推断独立存储与用户确认

对应既有方向 Issue #11。

- 完善推断的确认、拒绝、纠正和来源失效处理。
- 推断不得混入已确认事实检索；重复证据不能自动提高可信度。
- 形成 Foundation 是否接入独立审查工作流的产品评估。

### L-03 事实时间演化与多维召回

对应既有方向 Issue #12。

- 区分事实自然变化与真正冲突，保留历史视图。
- 评估时间、地点、情绪辅助混合检索的增益和误召回成本。
- 晋级前必须提供对 Foundation 现有裁决与召回行为的兼容测试。

### L-04 Dreaming 与动态用户画像

对应既有方向 Issue #8、#9。

- 后台增量回顾只生成可审查候选，不静默改写用户事实。
- 任务必须可恢复、可停止、可审计，模型调用和成本有上限。
- 画像允许用户查看、纠正和删除，来源失效时能够撤回或降权。

### L-05 跨 AI 客户端主动召回

对应长期方向 Issue #13。

- 以 MCP 和客户端实际能力为前提，不假设所有宿主都支持主动触发。
- 评估适时召回的收益、隐私边界和打扰成本。
- 不为了主动召回引入默认云同步或遥测。

## 6. 持续工程

### C-01 记忆质量评测与回归

对应 Issue #14。持续覆盖抽取、冲突、重复、时间变化、隐含召回、来源失效和敏感信息；使用合成数据和可复现基准，不用单次测试数量代替质量。

### C-02 数据迁移与恢复

每次存储格式变化都同步 dry-run、备份、apply、verify、幂等和恢复演练。旧内联推理和旧 Git 历史等既有数据边界必须显式说明。

### C-03 真实使用与成本观察

在明确授权和调用上限下进行真实模型 dogfood，记录失败类型、成本和使用体验；测试数据不进入公开仓库。

### C-04 文档与发布卫生

产品方向改 PRD，实施优先级改 Roadmap，模块和接口改架构文档，用户操作改中英文 README 与配置示例，历史证据留在日期化报告。

## 7. 从 Evo 晋级到 Foundation 的统一门槛

任何 Evo 高级能力进入 Foundation 前必须同时满足：

1. 有独立需求和明确用户收益，不是仅因为 Evo 已实现。
2. 不破坏 Foundation 现有检索、抽取、裁决、来源和更正语义，或已提供经批准的迁移方案。
3. 推断与事实分离，用户可查看、纠正、拒绝和删除。
4. 隐私、推理隔离、日志、Git 输入和模型回放经过检查。
5. 后台任务可恢复、可停止，具备锁和并发测试。
6. 合成基准证明质量收益，真实验收范围清楚。
7. Web、TUI、MCP 和直接调用路径的能力暴露一致。
8. 文档、迁移、构建和回滚方案齐备，并经项目所有者明确同意。

## 8. 明确不排入当前路线的事项

- 通用工作 Agent 和与 personal memory 无关的功能扩张。
- 默认云同步、遥测和多租户协作。
- Foundation 自动模型候补。
- 未经验证即宣称支持所有模型、搜索供应商、浏览器和手机平台。
- 仅为减少分支差异而覆盖 Foundation 的记忆业务。
