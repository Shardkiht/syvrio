# Syvrio Evo 路线图

- 适用分支：`feature-memory-evolution`
- 更新日期：2026-11-15

路线图按依赖和验收条件排序。实际进度以提交、CI 和验证记录为准。产品边界见 [PRD](PRD.md)。

## Now · 正式版收尾

| 工作 | 完成条件 |
| --- | --- |
| Foundation 稳定源码晋级 | 审查实际差异，验证合成 Vault 的 V1/V2 与 UTC 升级，经保护分支 PR 和 Debian CI 合入主线 |
| Web 手机实机验收 | 验证长流回复、后台返回、断网重连、主动停止、手动上滑和回到底部，记录设备及浏览器范围 |
| Evo 预发布收尾 | 确认版本、GitHub tag 和 PyPI wheel 对应；验证更新频道选择、健康检查及失败恢复 |
| 文档收口 | 保持两分支各自的产品规范与实际行为一致，旧方案按历史材料使用 |

## Next · 基础设施对齐

| 工作 | 完成条件 |
| --- | --- |
| 会话与前端 | 维护共用的 HTTP/SSE 和时间展示契约；覆盖会话切换、断线、游标、退出以及客户端互斥 |

| 主线同步 | 基础修复选择可独立验证的提交，保护稳定线的记忆行为；保留清晰的迁移及回退路径 |

## Later · Evo 高级记忆演进

| 工作 | 完成条件 |
| --- | --- |
| 结构化上下文与时间演化 | 日期精度、历史快照、事实修订和演化链的语义可重放；时间区间和多条件召回有合成回归 |
| 推断可信度 | 来源变更后自动重算有效视图；重复证据去重；确认、拒绝和纠错可追溯 |
| Dreaming 与画像 | 封闭写入和取消边界，约束模型预算；用固定语料测增量刷新、缓存失效、过期标记和候选质量 |
| 跨客户端主动召回 | 明确哪些 MCP 客户端实际调用了召回；比较有效命中、误召回和提示成本 |
| 质量评测 | 保留可重复的检索基准，测短字段、长描述、多语言和时间过滤；跟踪准确率与响应分位耗时 |

## 从 Evo 晋级到稳定线

提交应可单独审查，并对应回归和实际使用场景。涉及存储时要验证备份、迁移、旧格式拒绝和可恢复性。涉及后台调度时要验证写锁、取消、重试和退出。高级记忆功能未经稳定验收继续留在 Evo。源代码合入、PyPI 发布、GitHub Release 与生产更新各有独立验收状态。
