## 阅读顺序

- **了解产品方向**：PRD → Roadmap。
- **开始开发**：PRD 中相关边界 → architecture → AGENTS → 对应技术规范。
- **做代码 Review**：architecture → AGENTS → 源码与测试 → 当前验收报告。
- **迁移 Vault**：先停写并备份，再严格按 vault-v2 和 time 的顺序执行。
- **查历史原因**：确认现行文档后，按需要查阅 Git 历史。

## 冲突处理

1. 产品方向以最新明确修订的 PRD 为准，技术事实必须能由源码和测试核验。
2. 文档与代码不一致时，不得悄悄选择对自己方便的一方；先记录差异，再决定是代码回归还是经批准的需求/设计变更。
3. 历史文档与现行文档冲突时，不直接修改历史证据；在现行文档中写明新决定。
4. 固定测试数量、临时路径、真实验收状态和发布状态放在日期化报告中，不写进长期架构规范。
5. 新增长期文档时更新本索引，避免再次出现同一决策散落在多处且无法判断新旧的问题。
