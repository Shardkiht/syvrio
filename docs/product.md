# Syvrio 产品需求与路线图

- 适用分支：`main`（唯一长期开发分支）
- 文档状态：当前主线产品基准，主线与已发布版本分别核验
- 更新日期：2026-11-28

本文说明产品定位、可用能力及验收要求。实现细节见 [架构](architecture.md)、[存储与恢复](storage.md) 和 [Web 指南](web.md)；具体待办以 [GitHub Issues](https://github.com/Shardkiht/syvrio/issues) 为准。

## 产品定位

Syvrio 是面向个人的本地优先记忆助手。它让有用的事实、偏好和计划跨会话生效，同时保留来源和修改历史。正式事实、待审候选、推断和画像分开管理：记录过什么、模型推断出了什么，以及用户确认了什么，可以分别查看。

Vault 的业务数据以本机 SQLite 为准。Web、TUI、CLI 和 MCP 共用同一常驻后端，不各自读写一个 Vault。Git 用于导出可阅读、有历史的副本，不是在线主库，也不替代完整备份。接入外部模型、联网搜索或共享网页时，按各自配置使用外部服务；本地优先不等于所有请求均离线。

## 用户场景

| 场景 | 用户需要 | 验收示例 |
| --- | --- | --- |
| 跨会话协作 | 不必重新说明已经确认的偏好、约束和计划 | 在独立会话召回此前保存的有效事实，并能追到原会话和消息 |
| 更正与变化 | 区分记错了和后来变了 | 更正沿用事实 ID 并保留版本；状态变化保留在当时真实成立的旧事实 |
| 审核与维护 | 看到待审记录、推断依据与正式事实之间的重复和矛盾 | 核对原文及来源后确认、修订或忽略；未经采纳的维护建议不混入召回 |
| 断线与多端 | 刷新、切换会话或断线后仍能回到同一轮 | 重连续读原回复；按原发送编号重试不会重复保存已送达的用户消息 |
| 搬机与恢复 | 完整数据能独立恢复，历史也能方便查看 | 备份恢复到新目录后能读取会话和附件；编辑 Git 导出不反写主库 |

## 功能要求与验收

| 编号 | 能力 | 当前行为与验收口径 |
| --- | --- | --- |
| FR-01 | 会话与上下文 | 支持创建、切换、历史浏览、归档、停止、撤销和压缩；Web 与 TUI 共用会话内命令。生成期间会话间可独立进行；同一会话按队列处理。断线不等于取消，已保存的用户消息与送达回执一起提交，回复独立保存。 |
| FR-02 | 记忆写入与候选 | 聊天记忆提案编号独立；写入前经召回复核，再决定写入、待审或跳过。可识别的凭据不进入记忆。改写并确认候选后保存最终正文，再从可信来源补齐有依据的空字段。 |
| FR-03 | 召回 | 支持关键词、向量和混合检索，也可按日期范围、地点和情绪筛选。向量不可用时验证关键词回退；验收分别看短词、长描述、多语言和时间条件。 |
| FR-04 | 更正与状态变化 | `correct` 在原 ID 上修正错误并保留版本；`transition` 为真实变化建立历史关联；`deprecate` 弃用不再应被召回的事实。审计保留来源和变更，日期保留年、月或日的原始精度。 |
| FR-05 | 推断与画像 | 推断与正式事实分别存储，推断可追溯到引用时的事实版本，并可和当前版本对照。Dream 依据本轮固定证据生成画像与待审推断；失败可从已提交进度继续。来源修正不自动取消已确认推断；`/profile` 展示最近发布的画像。 |
| FR-06 | 记忆维护 | 定时或手动检查正式事实的重复、矛盾，生成独立维护建议。Web 的 Pending 面板可核对来源并确认保留一条、记录状态变化或忽略。批准时重新核对双方版本；扫描本身不改事实。维护与 Dream 各自运行，不共用进度。 |
| FR-07 | 模型、搜索与抓取 | 从供应商目录选择模型，切换对新回合生效；搜索和网页抓取分别配置。搜索做去重和规则重排，可设自动回退、两家对照或限定供应商；额度、空结果和未完成交叉验证必须据实呈现。搜到的内容是外部资料，不当作指令或已经核实的事实。 |
| FR-08 | 客户端与附件 | Web、TUI、CLI 和 MCP 共享一个常驻后端；一个物理 Vault 只允许一个常驻后端占用，可同时连接多个客户端。Web 和 TUI 只上传用户明确选择的本机文件；能在历史中查看附件，归档不等于永久删除。 |
| FR-09 | 备份与升级 | SQLite 主库和已引用附件可完整备份并恢复到新目录；Git 导出不包含数据库或附件原件。受管更新从 PyPI 选择正式版，使用兼容解释器，失败时验证旧服务能恢复。存储格式不兼容时单独核对迁移，不能把包升级视作自动完成迁移。 |

## 质量与交付

- 对外示例和回归优先使用合成数据。真实记忆、附件、凭据及未公开的会话详情不进入源码仓库或评测输出。
- Web 默认本机监听。需要远程访问时使用受信网络或带身份校验的共享入口；不要把不带内置登录的网关直接暴露到公网。
- 存储、后台和客户端验收分别验证数据恢复、整轮固定证据视图、重试和断线行为。供应商实测与合成评测分开记录，真实手机测试注明设备和浏览器。
- 主线合入、GitHub Release、PyPI 发布和生产更新是不同的交付步骤。本文以主线实现为准，不意味着所有改动已发版或部署。

## 路线图

| 方向 | 后续验收重点 |
| --- | --- |
| 对话与客户端 | 补齐 iOS Safari 和 Android Chrome 实机验证：软键盘、长回复、后台切回、断线重连与附件。持续验证批量后台写入时的前台响应。 |
| 记忆与维护 | 用可追溯样例验证真实变化、历史更正、候选冲突和证据过期。分别衡量沉淀、Dream 和维护的误判，避免把待审或衍生信息当作已确认事实。 |
| 搜索与模型 | 区分上游漏召回、重排误伤和早停漏查；用固定候选复验规则，用受控真实请求验证供应商稳定性和失败回退。 |
| 部署与恢复 | 持续验证正式 wheel、Web 静态资源、SQLite 备份与恢复，以及升级失败后的回滚；历史格式导入单独验收。 |
